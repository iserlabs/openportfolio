# apps/site — working notes

Single-owner portfolio app: public pages render the owner's
`social.opencontent.*` records from a pinned PDS; `/admin` is the owner-only
CMS that writes them back. No Postgres — one SQLite file (`SQLITE_PATH`)
holds OAuth state/sessions and the blur cache, nothing canonical.

## Route map

- `app/(public)/` — home `/`, `/p/[rkey]` (photograph), `/c/[rkey]`
  (collection), `/about`. Public pages read **only** through
  `lib/portfolio.ts`'s `getPortfolio()`, never `lib/pds.ts` directly.
- `app/admin/` — owner-gated CMS: dashboard, `upload/`, `collections/`,
  `site/`, `login/`, `export/` (streams the whole repo as a CAR, never
  buffered), `api/prefill/` (EXIF/IPTC prefill for the upload form).
- `app/oauth/` — `callback`, `client-metadata.json`, `jwks.json` (all derived
  from `PUBLIC_URL` via `lib/oauth.ts` so metadata and client agree
  byte-for-byte).
- `app/img/[cid]/[preset]/` — re-encoding image proxy (see pipeline below).
- `app/.well-known/atproto-did/` — handle-verification endpoint.

## Server actions pattern (app/admin/actions.ts)

Every mutation is split for testability, mirroring Luminance's
`photo/actions.ts`:

- `*Core(ownerDid, agent, formData, deps)` — the real logic. Takes an
  already-resolved DID + PDS `Agent`, returns a result object
  (`{ok:true,...} | {ok:false,error,code?}`), never throws to the client.
  `ownerDid === null` is the testable "not the owner" branch. `deps` is a
  partial override bag (`stripGps`/`extractPrefill`/`bustCache`) so unit
  tests inject stubs.
- The exported action (`publishPhotograph`, `saveCollection`,
  `deleteRecordAction`, `saveSite`) is a thin shell: `requireOwner()` →
  `restoreAgent(did)` → `*Core(...)`, all in a blanket try/catch mapping any
  throw to a generic error.
- Client forms build their `FormData` via the colocated `*-form-data.ts`
  helpers (`upload/publish-form-data.ts`, `collections/collection-form-data.ts`,
  `site/site-form-data.ts`) — keep field encoding there, not inline in
  components. Collections: absent `rkey` ⇒ `createRecord`, present ⇒
  `putRecord`; reorder = resubmit `items` in the new order.
- Every successful write calls `bustCache()` so the public read model updates
  immediately (see below).

## OAuth (confidential client)

- `lib/oauth.ts`: ATProto **confidential** `private_key_jwt` client. Signing
  key is the per-install ES256 JWK in `OAUTH_JWK` (generated by
  `deploy/setup.sh`; must carry a `kid` — the library rejects keys without
  one).
- Scope is `atproto transition:generic` — the bare `atproto` scope cannot
  upload blobs or write records (`ScopeMissingError`). Don't "simplify" it.
- `getOAuthClient()` is **cached per config**. Never build a fresh
  `NodeOAuthClient` per request: the DPoP-nonce cache lives on the instance,
  and a cold cache triggers a nonce-retry path that crashes on non-replayable
  bodies under Next's server — breaking every post-login PDS write.
- State + sessions persist in SQLite (`lib/db.ts`: `oauth_states`,
  `oauth_sessions`; WAL; idempotent `CREATE TABLE IF NOT EXISTS`, no
  migration runner). Stale states are pruned by the scheduler tick.
- Anyone can complete the OAuth flow; authorization is separate:
  `lib/session.ts`'s `requireOwner()` only passes when the session DID equals
  `OWNER_DID` (iron-session encrypted cookie).

## Data spine

- `lib/env.ts` — lazy getters; importing it must never throw (`next build`
  runs with zero env vars). Keep new env vars in this pattern.
- `lib/pds.ts` — pinned public reads against `PDS_URL` only (never a
  caller-supplied origin): bounded-paging `listAllRecords` (5000-record /
  50-page hard cap), `getRecord` (null on missing, both 404 and
  `RecordNotFound` wire shapes), `blobUrl`, and the process-wide `cached()` /
  `bustCache()` TTL store shared by reads and admin writes.
- `lib/portfolio.ts` — `getPortfolio()` is the single read model for public
  pages (60s TTL, busted on every admin write). Deps are injectable
  (`PortfolioDeps`: `getRecord`/`listAllRecords`/`cached`) so tests exercise
  the pure core (`assemblePortfolio`, `collectionPhotographs`, `homeFeed`,
  `neighborsInCollection`) with stand-ins. Consumer contract: dangling
  strongRefs and dangling `collectionOrder` entries are skipped silently,
  never errors; unlisted collections append newest-first.

## Image pipeline

- `app/img/[cid]/[preset]` → `lib/image-proxy.ts`. Presets: `thumb` 512 /
  `grid` 768 / `feed` 1024 / `full` 2048. Allowlist first: a cid is only
  proxied if it's some photograph's blob cid (404 before any upstream fetch —
  no SSRF surface). sharp re-encodes to AVIF/WebP/JPEG by `Accept`;
  originals are never served to browsers directly.
- First successful serve also writes a ~16px blur-up placeholder (webp data
  URI) to the SQLite `blur` table — best-effort, never fails the real
  response. Pages read placeholders via `lib/blur.ts`.
- **All image URLs go through `lib/img-src.ts`** (`imgSrc`, `imgSrcSet`,
  `absoluteImgSrc` for OG tags) — one place to change if the proxy URL shape
  ever does.
- Upload accepts jpeg/png/webp/avif/heic MIME types, but genuine HEIC bytes
  are honestly rejected by `lib/photo-metadata.ts`'s `extractPrefill` with an
  actionable message — this build's libvips decodes `.avif` only (HEVC
  licensing). Don't try to "fix" HEIC by widening the accept list.
- GPS is stripped by default, and only when actually present (`hasGps`);
  AVIF-with-GPS is refused outright (exiftool's AVIF write path is
  unreliable) rather than risking geotagged bytes shipping. Masters are never
  recompressed — the only re-encode is `upload/downscale.ts`, a client-side
  opt-in after a `too-large` rejection.

## Tests — three layers, three configs

| Config | Scope | Run | Where it runs |
|---|---|---|---|
| `vitest.config.ts` | Unit: colocated `*.test.ts` in `lib/` and `app/` (node env, no DOM; excludes `integration/`, `e2e/`) | `pnpm test` | CI + local |
| `vitest.integration.config.ts` | `integration/` against a real `@atproto/dev-env` PDS (SQLite-native, no Docker; serial, generous timeouts) | `pnpm --filter site test:integration` | Local/nightly only |
| `playwright.config.ts` | `e2e/` author-loop: real OAuth in real Chromium against a dev-env network + production build. `e2e/global-setup.ts` owns the whole server lifecycle (no `webServer` — env is only known after setup boots the network) | `pnpm --filter site test:e2e` (first run: `pnpm --filter site exec playwright install chromium`) | Local/nightly only |

Run the integration + E2E suites yourself before trusting changes to the
publish/OAuth path — CI only runs build + typecheck + unit.

## Backups / instrumentation

- `instrumentation.ts` registers `lib/backup-scheduler.ts` under the Node
  runtime only, via a **dynamic** `import()` — a top-level import breaks the
  Edge build (better-sqlite3 native addon). Don't convert it.
- Daily tick: `runBackup()` (CAR + blobs to `BACKUP_DIR`, temp-then-rename so
  files at the real path are never truncated; no-ops when `BACKUP_DIR` unset)
  plus `pruneOauthStates()` (always, backups configured or not).

## Conventions

- Some route files (e.g. `app/admin/export/route.ts`,
  `app/admin/api/prefill/route.ts`) use relative imports instead of the
  `@/*` alias, with colocated tests — match each file's existing style.
- `@openportfolio/lexicons` is a mirror of the sibling `opencontent-lexicons`
  repo. Never invent or change record shapes here; the site record's rkey is
  always `"self"`, and `fNumber` stays a string.
